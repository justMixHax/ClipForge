# Code review by ChatGPT (gpt-6.2-astra) through Codex

Reviewed: the ChatGPT second opinion and the work log, before they were committed, on 2026-11-22. All 11 findings were fixed in the same change; each fix has a test.

The default second opinion breaks the existing local-only privacy guarantee, and neither new Codex workflow reliably enforces its promised authentication boundary. The optional review can also fail or block the entire analysis instead of preserving the primary picks.

Full review comments:

- [P1] Preserve local-only analysis when upgrading existing settings — backend\app\services\settings_store.py:64-64
  **Fixed: with Local rules only, the second opinion is skipped and its setting is locked off.**
  An installation that previously selected “Local rules only” has no stored `ai.second_opinion` value, so it inherits `chatgpt` on upgrade. On the next analysis with speech and picks, `_analyze` sends the transcript, title, and creator to ChatGPT without the user changing a setting. This breaks the explicit local-only guarantee in `SECURITY.md:63-64`. Keep the second opinion off for those installations unless the user explicitly enables it.

- [P1] Require ChatGPT authentication before sending a transcript — backend\app\analysis\chatgpt_review.py:61-62
  **Fixed: Codex must report "Logged in using ChatGPT" or nothing is sent; CODEX_API_KEY is removed too.**
  Removing `OPENAI_*` variables does not guarantee plan-based authentication: `codex exec` can use `CODEX_API_KEY`, and `--ignore-user-config` still loads credentials from `CODEX_HOME`, which may hold an API-key login. In either setup, analysis or the connection test can consume paid API credits despite the no-API-key promise. Require ChatGPT login mode and treat other credential modes as unavailable.

- [P1] Disable tools for transcript-only reviews — backend\app\analysis\chatgpt_review.py:66-68
  **Fixed: shell, file viewing, browser, computer use, apps and plugins are switched off for these runs.**
  The Codex invocation leaves shell tools available while passing imported transcript text as part of the prompt. A read-only sandbox limits writes; it does not limit reads to the transcript or make the instruction “do not run commands or open files” enforceable. A review steered by the source material can therefore pull readable local data into the model context. Use a tool-free invocation for this text-only task, as the Claude integration does.

- [P1] Isolate the code-review script from configured providers — scripts\review.ps1:34-35
  **Fixed: the script checks the ChatGPT sign-in and forces OpenAI's own provider.**
  The script clears some environment variables but invokes `codex review` with the user's normal provider configuration. If that configuration selects a relay or API-backed provider, the repository diff goes there rather than through the promised ChatGPT sign-in. The model override does not override the provider. Isolate provider configuration and verify ChatGPT authentication before submitting repository content.

- [P2] Reject malformed review collections without failing analysis — backend\app\analysis\chatgpt_review.py:135-138
  **Fixed: wrong shapes are refused cleanly, and any unexpected error keeps the picks.**
  A valid JSON response such as `{"verdicts":1}` passes the top-level check and then raises `TypeError` when the parser iterates it. `_analyze` catches only `ChatGPTUnavailable`, so a malformed optional review fails the job before it saves the primary picks. Validate that `verdicts` and `additions` are lists and route unusable responses through the existing fallback.

- [P2] Treat an unlaunchable Codex executable as unavailable — backend\app\analysis\chatgpt_review.py:175-178
  **Fixed: a tool Windows will not start counts as unavailable (Claude's too).**
  `find_cli` can locate an executable that the OS refuses to start, for example when Windows application control blocks it. `Popen` then raises `OSError`, not `ChatGPTUnavailable`. This discards an otherwise successful analysis and makes `/system/ai/test` return a server error instead of showing the other provider's result. Translate launch failures into the existing provider-unavailable error.

- [P2] Apply cancellation and timeout while writing the transcript — backend\app\analysis\chatgpt_review.py:179-185
  **Fixed: the prompt is passed from a file, so nothing can block (Claude's too).**
  The full transcript is written synchronously to a pipe before the timeout starts or cancellation is polled. If Codex stalls before consuming stdin and the transcript exceeds the pipe buffer, the worker blocks in `write()` indefinitely; neither cancelling the job nor closing the app reaches the kill loop. Use a bounded, cancellable input transfer or give the child a prepared file as stdin.

- [P2] Enforce the selected clip length on ChatGPT additions — backend\app\analysis\engine.py:391-393
  **Fixed: picks and additions must fit the chosen length (with a little leeway).**
  The prompt requests the selected length range, but `highlights_from_picks` accepts any snapped clip from 3 seconds to `max_len + 15`, regardless of `min_len`. For example, a user asking for 60–90 seconds can get a five-second addition saved and automatically rendered. Validate the final addition boundaries against the selected range rather than relying on the model to honor it.

- [P2] Save the final review rather than the CLI execution trace — scripts\review.ps1:43-43
  **Fixed: only the final review is saved; this file was trimmed to it.**
  The script merges Codex progress on stderr with the final review and writes the entire stream to a Markdown file intended for Git. On a normal review this can include command output, source excerpts, and local paths that are not part of the findings. Keep diagnostics separate and persist only the final review, so committing the report does not also publish the agent's working log.

- [P2] Fetch the work log in completion order before applying the limit — frontend\src\components\WorkLog.tsx:44-47
  **Fixed: the work log asks for jobs in finishing order.**
  `/jobs` sorts by queue status and priority before ID, not by finish time. Render jobs have higher priority than analysis jobs, so old renders appear ahead of a newly completed analysis; after 60 renders, the analysis can disappear from this view altogether. Request finished jobs ordered by `finished_at` descending before applying the limit.

- [P3] Skip rescoring setup when the review has no additions — backend\app\analysis\engine.py:391-393
  **Fixed: no rescoring when ChatGPT adds nothing.**
  A verdict-only review still calls `highlights_from_picks`, which constructs a `ScoringContext` and prepares the entire transcript, audio, and visual features before discovering there are no picks to score. On long videos this repeats a full preparation pass to produce an empty list. Skip the call when `review.additions` is empty.
