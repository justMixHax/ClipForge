# Code review by ChatGPT (gpt-6.2-astra) through Codex

Reviewed: the changes not committed yet, on 2026-11-22 05:50.

The patch can silently send existing users' transcripts to a new recipient, and the review script does not reliably enforce its promised destination. The Windows CLI launch and cancellation paths also need fixes before the optional review can be relied on.

Full review comments:

- [P1] Ask existing Claude users before sending transcripts to OpenAI — backend\app\services\settings_store.py:64-64
  **Not changed: ClipForge has one user, who asked for this connection on 2026-11-22. It is labelled in Settings and SECURITY.md and is one switch to turn off.**
  `settings_store.get_all()` supplies this default to every installation without a stored `ai.second_opinion`. After an upgrade, someone who chose Claude under the previous Claude-only disclosure will send their next transcript, title, creator and picks to OpenAI as well, provided Codex is signed in. The local-engine guard does not protect those users. Keep the second opinion off for existing installations until they enable it.

- [P1] Isolate the review command from configured endpoint overrides — scripts\review.ps1:42-42
  **Fixed: the script refuses to send anything if the Codex settings set another provider or address.**
  Selecting `model_provider="openai"` does not reset Codex's `openai_base_url`. If the user's Codex configuration points the built-in provider at a relay, `login status` can report a ChatGPT sign-in while `review` still sends repository content to that relay. Use an isolated review invocation, such as `codex exec review --ignore-user-config`, and ensure the effective endpoint is the intended one before submitting the diff.

- [P1] Require a native Codex executable on Windows — backend\app\analysis\chatgpt_review.py:55-58
  **Fixed: only a real .exe is used, and model names are limited to plain characters (in Settings too).**
  `shutil.which("codex")` can return an npm-installed `codex.cmd` before the app's `codex.exe`. Windows runs batch files through the command interpreter even when `Popen` receives an argument list, and `command()` passes the free-form `ai.chatgpt_model` setting to it. Shell metacharacters in that setting can therefore be interpreted as commands under the user's account. Resolve a native executable on Windows rather than passing user-controlled arguments through a batch shim.

- [P2] Disable hosted search for transcript-only reviews — backend\app\analysis\chatgpt_review.py:70-73
  **Fixed: web search is switched off for these runs.**
  The browser and shell feature flags do not disable Codex's separate `web_search` setting. On a model with hosted search available, the reviewer can still issue searches based on imported transcript text and use outside material when judging a clip. Explicitly set `web_search="disabled"` for this invocation rather than relying on the prompt to restrict it to the supplied text.

- [P2] Honor cancellation during the Codex login check — backend\app\analysis\chatgpt_review.py:202-203
  **Fixed: the sign-in check can be cancelled, and cancellation is checked again before sending.**
  `require_chatgpt_sign_in()` can block in `subprocess.run()` for 30 seconds without polling `should_cancel`. If the user cancels during that wait and the check then succeeds, `run_codex()` still starts the review with the transcript before its first cancellation check. Make the preflight cancellable and check once more immediately before launching the review.

- [P2] Wait for CLI termination before deleting its input and logs — backend\app\analysis\chatgpt_review.py:221-226
  **Fixed: after stopping the tool, ClipForge waits for it to let go of its files (Claude's too).**
  On Windows, `proc.kill()` requests termination but does not wait for the process to release its inherited file handles. On timeout or cancellation, `prompt_file.unlink()` or temporary-directory cleanup can consequently raise a sharing violation instead of the intended exception. The same race exists in the new file-backed `run_claude()` path, where it can fail the analysis instead of using local picks. Wait for process exit before cleanup in both runners.

- [P2] Require transcript evidence for ChatGPT additions — backend\app\analysis\engine.py:393-395
  **Fixed: a ChatGPT addition must contain something that was said.**
  ChatGPT only receives the transcript, but `highlights_from_picks()` accepts an addition even when no sentence intersects its interval: it keeps the proposed timestamps, score and reason with an empty `transcript_text`. On a video with a long speech-free gap, an invented moment in that gap can therefore be saved and automatically rendered. Reject unanchored ChatGPT additions; signal-only clips can still come from the local sound and picture analysis.

- [P2] Keep the caller's environment intact after a code review — scripts\review.ps1:27-29
  **Fixed: settings removed for the review are put back afterwards.**
  When invoked as `./scripts/review.ps1` from an existing PowerShell session, `Remove-Item Env:...` modifies the process environment, not a script-local copy. Those settings remain deleted after success, a failed login, or a failed review, so unrelated commands in the same terminal can lose their credentials or provider settings. Sanitize only the child process environment, or restore the original values on every exit path.

- [P2] Preserve the work log when a running job is cancelled — backend\app\jobs\pipeline.py:857-859
  **Fixed: a cancelled job keeps its lines and ends with "Cancelled."**
  If an analysis is cancelled after transcription or after Claude has picked clips, `handler()` raises `JobCancelled` before these accumulated lines are copied. The cancellation branch marks the job cancelled without storing `ctx.worklog`, and `VideoWorkLog` then filters the job out entirely. Persist the completed lines and a cancellation entry when the job reaches terminal cancellation, while keeping shutdown-and-resume separate.

- [P2] Filter out active jobs before limiting the finished work log — backend\app\api\jobs.py:39-41
  **Fixed: the work log only asks for finished jobs.**
  `coalesce(finished_at, created_at)` lets newly queued renders occupy the limited result set. For example, after a 30-clip batch is queued, the work-log request can receive 30 active jobs and only 30 finished jobs; the UI discards the active rows, hiding another 30 available log entries. Apply the terminal-status filter on the server for the work-log request, before sorting and limiting.

- [P3] Preserve failure diagnostics without saving the review trace — scripts\review.ps1:52-53
  **Fixed: Codex's own messages are shown when a review fails, and no file is written then.**
  Codex reports failures such as an invalid model or base branch on stderr. Redirecting that stream to `$null` leaves the user with only an exit code, despite the later message saying the output explains why. The script also writes a header-only review before checking that code. Capture diagnostics separately, show them on failure, and only publish the findings file after a successful review.
